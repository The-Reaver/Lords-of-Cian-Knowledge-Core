## Update 2026-08-31 (evening) — five artifacts added plus one updated (stag-13 session, Cultivation Program Layers 1–3; self-registered, pending the operator's ratification pass)
- loop-registry-and-heartbeat-gate: The Loop Registry and its heartbeat gate (created 2026-08-31, commit b4553e0). `governance/loops.json` + `scripts/gates/loop_heartbeat_gate.py` + 40 tests + a prose pointer at `research/knowledge-home/structure-notes/loop-registry.md`. The structural answer to this fleet's one recurring failure: a loop gets built, assigned to a named reviewer with no forcing function, and quietly stops turning. A loop now declares four things or does not count as existing — a named owner that is a specific seat and never a role in the abstract, a scheduled invoker, a deadline with defined miss behaviour, and a heartbeat. Nine loops seeded, all `proposed` rather than `active`, because none had both a real invoker and a provable last_run, and marking them active would have been the same overclaim the registry exists to stop. Staleness is tiered WARN-then-FAIL, not binary, so a loop that slips slightly does not break a commit for everyone sharing the checkout. Invoker verification is type-aware: repository content via `git ls-files` in the owning repo, `hook` invokers via the resolved hooks dir, because installed hooks are tracked in no repository and a blanket ls-files test would false-fail every correctly installed one. PROVEN, NOT MERELY TESTED: backdated a real loop to 3x cadence (FAIL), 1.6x (WARN, exit 0), restored (PASS), removed the temp loop and confirmed the registry was content-identical. KNOWN LIMIT: `cron` and `scheduled-task` invoker verification expects a tracked repo-relative definition file and has never been exercised; if this machine schedules via Windows Task Scheduler with nothing in the repo, the gate cannot see the invoker at all. Answer that before promoting any loop to `active`. Draws from: governance/loops.json, scripts/gates/loop_heartbeat_gate.py, tests/test_loop_heartbeat_gate.py, reports/BRIEF_S1_LOOP_REGISTRY_2026-08-31.md.
- installed-hook-gate: Installed-hook verification gate (created 2026-08-31, commit 5b7eb93). ITS LIVE PROOF RAN 2026-08-31, against a shallow clone in temp rather than the live tree, because three sessions commit into the shared checkout continuously and removing `pre-commit` even briefly means a commit lands with zero gates.
